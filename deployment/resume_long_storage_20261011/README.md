# Resume the original Long external-HR stage

The original Long run completed CPU preparation, initialization, full HR
expansion, registration, Z5 and its28-task table. Its external-HR rsync exited10
before canonical synchronization or GPU dispatch. This adapter resumes missing
files in that same external stage, `long360_seed07_storage_20261011t061138z`,
while using fresh coordinator/startup/pipeline/service output identities.
It does not allocate another full HR stage or modify the original failure.

The operator has collected the original inventory once, using the unchanged
collector and frozen event020 inputs. Spec creation requires `--inventory` to
reuse that exact JSON; it hashes the JSON reference, not the38GB input tree.
It does not rerun CPU preparation, Z5, initialization, HR expansion or table
generation. The inventory schema, destination,65GB future allocation and
original final freeze must match the original run.

First the original additive synchronizer copies all inventory entries outside
the external-HR prefix. This includes every prepared LR image, cam00 evaluation
HR and cam01's ten prepared HR diagnostic frames. Its separate
`early_inputs_sync` output keeps the original final sync's filenames unused.
GPU0 then runs the original50-step/three-frame startup once.

After that acceptance, a fresh persistent early-LR service selects only the
exact coarse/fine tasks from the original complete28-task table. It calls the
original `execute` and `check_completion` with their unchanged argv, outputs
and3000+14000 updates. It reuses the actual startup source identities and frozen
namespace inventory. It holds only GPU0's original UUID claim. In parallel,
the coordinator continues the original external-HR missing-file transfer.
The wait thread writes only its independent native-exit receipt; it does not
change coordinator stages or serial events. Neither path polls a model.

Before transfer, an owned Python-c helper loads the SHA-pinned original storage
helper. It verifies ownership, package/binary, existing stage/canonical paths,
every existing file's size/SHA and the external60GB reserve. A different or
unexpected file stops recovery and is preserved. Only missing files are sent
using the original exFAT-safe rsync argv, including `--ignore-existing` and
`--protect-args`. The original complete SHA verify/mount/mount-check then runs
with the old storage run ID. Its read-only FUSE mapping and package/process
identity rules are unchanged. The original canonical sync retains65GB future
output and60GB root reserve guards and rejects differing existing files.

The original startup's prerequisite validator fixes Long to GPU1. The owned worker
therefore calls that CPU-only validator with a copied argument namespace using
its original index1, while its original execution function receives the actual
authorized GPU0 index/UUID and checks hardware normally. This operational
GPU1→GPU0 adaptation is recorded; it is not an unmodified startup allocation.
The original scientific inputs and training process remain unchanged.

Each owned startup/early-LR/runner
Python-c entry waits2seconds before each original idle check, then reads once
with unchanged1024MiB/10% limits. Only the authorized GPU0 may admit the verified
`gnome-remote-desktop-daemon` at the original600MiB graphics limit. Other compute
processes remain rejected. This buffer is not a guarantee that a card is idle.
Startup resources check GPU0 only. Before the full DAG, both the storage path
and the native early-LR unit exit must succeed, and the early GPU0 claim must be
released. The original full DAG validates and skips the two original completed
LR tasks; it does not repeat their training. Its existing evaluation and other
tasks then follow their original dependencies. The full runner independently
requires both original GPU UUIDs to pass actual prelaunch checks. If GPU1
remains busy, formal dispatch is rejected and completed evidence is preserved.
Any transfer or early-service failure prevents full-DAG dispatch. An already
running early service is allowed to exit; no duplicate service is submitted.
Another task using GPU1 is protected. No task is killed, polled in a retry loop,
automatically restarted or added to the training grid. The early service logs,
completion receipts and both original LR checkpoint directories are returned
when the coordinator joins its native exit, before full-DAG dispatch. They are
preserved locally even if HR synchronization fails or the full-DAG resource
check rejects a busy GPU1. Full results also remain included in the original
final pull.

The adapter uses direct `ssh a100-train`, without changing SSH configuration.
Only the final original headroom CPU analysis is allowed. Old scientific and
storage source files, original specs, budgets, frame populations and paths remain
unchanged. New source/worker/helper identities and operational route changes are
recorded in the fresh spec and logs. The owned read-only mount remains available
for later audited rerenders; recovery does not unmount it or delete partial data.

These commands only inspect existing local identities and create a local spec.
They do not recreate the inventory, connect to A100 or launch GPU work. The root operator
starts `--spec` as a new persistent local service. No automatic retry or extra
training branch is provided.
